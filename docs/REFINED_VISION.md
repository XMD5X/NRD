# Админ-панель поддержки для запуска скриптов и самообслуживания бизнес-заказчиков

## Проблема

Сотрудники ИТ-поддержки вручную запускают PowerShell/Python/Bash скрипты через RDP/SSH напрямую на серверах. Это создаёт риски безопасности (широкий доступ к серверам), отсутствие единого аудита выполненных действий и высокий порог входа для непрофильных пользователей. Кроме того, часть операций (например, настройка прав доступа к банковским документам, загрузка сертификатов) вынуждает бизнес-заказчиков обращаться в ИТ вместо самостоятельного выполнения.

## Решение (краткое описание)

Веб-панель, через которую:
- ИТ-администраторы добавляют и запускают скрипты (PowerShell/Python/Bash), видят статус выполнения и результат;
- бизнес-заказчики самостоятельно выполняют ограниченный набор операций (загрузка сертификатов, счетов, настройка полномочий) без обращения в ИТ.

Скрипты выполняются на отдельной машине от веб-панели, взаимодействие между веб-слоем и слоем выполнения — через API. Все действия пользователей логируются в БД (бизнес-аудит) и на фронтенде (технические логи 4 уровней).

## Целевая аудитория

- **ИТ-администраторы** — настраивают систему, добавляют скрипты через UI, имеют полные права на все действия.
- **Бизнес-пользователи (заказчики)** — используют ограниченный набор функций: загрузка сертификатов, счетов, управление полномочиями по своим данным.

## Ключевые сценарии использования

**US-1. Вход в систему**
- Given пользователь имеет учётные данные в системе,
- When он вводит логин и пароль на странице входа,
- Then при успешной проверке открывается главная страница панели с доступным ему набором действий согласно роли.

**US-2. Администратор добавляет новый скрипт**
- Given администратор авторизован в панели,
- When он загружает файл скрипта (PowerShell/Python/Bash) через UI,
- Then скрипт появляется в списке доступных задач (поля ввода параметров настраиваются разработчиком отдельно, не через UI в MVP).

**US-3. Запуск скрипта пользователем**
- Given пользователь видит в выпадающем списке доступную ему задачу,
- When он выбирает задачу, вводит требуемые параметры и запускает выполнение,
- Then система взаимодействует со слоем выполнения скриптов по API, а по завершении показывает статус "успешно/ошибка" и (если применимо) предлагает скачать файл результата.

**US-4. Бизнес-пользователь загружает сертификат/счета/полномочия**
- Given бизнес-пользователь авторизован в панели,
- When он выбирает соответствующую задачу и загружает нужные данные (сертификат, номера счетов, права),
- Then запрос обрабатывается системой (генерация файла и/или вызов API — в зависимости от скрипта), результат отображается в UI.

**US-5. Администратор блокирует пользователя**
- Given администратор просматривает список пользователей,
- When он вручную блокирует конкретного пользователя,
- Then заблокированный пользователь больше не может войти в панель, событие фиксируется в истории действий.

**US-6. Просмотр истории действий**
- Given администратор находится в разделе аудита,
- When он открывает историю действий пользователя,
- Then он видит логины, попытки авторизации, статус блокировки и выполненные действия по датам.

## Границы MVP

**Входит в MVP:**
- Вход по логину/паролю, учётные записи хранятся в собственной БД системы (без интеграции с AD).
- Две роли: Администратор (полные права) и Бизнес-пользователь (ограниченный функционал), роль назначается вручную администратором в БД.
- Выпадающий список доступных задач (скриптов) с учётом роли пользователя.
- Добавление скриптов администратором через UI (без самообслуживания по настройке параметров — это делает разработчик).
- Запуск скриптов с параметрами, взаимодействие со слоем выполнения по API.
- Отображение статуса выполнения ("успешно/ошибка") и скачивание файла результата, если он создаётся.
- Загрузка сертификатов, счетов, управление полномочиями бизнес-пользователем.
- Ручная блокировка пользователя администратором.
- История действий пользователя, история авторизаций — в БД.
- Файловое логирование фронтенда с уровнями INFO/DEBUG/WARNING/TRACE, доступное разработчикам и администраторам.

**Вне MVP (отложено):**
- Интеграция авторизации с Active Directory (доменный вход, проверка группы X).
- Ролевая модель на основе доменных групп.
- Автоматическая защита от подбора пароля (блокировка после N неудачных попыток).
- Самообслуживание администратора по настройке полей ввода параметров скрипта через UI.

## Метрики успеха

- Снижение числа обращений в ИТ-поддержку на добавление полномочий и загрузку сертификатов (переход на self-service бизнес-заказчиками).

## Бизнес-ограничения и допущения

- [ASSUMPTION] Автоматическая блокировка после подбора пароля (порог попыток, время блокировки) — вне MVP, будет уточнено на следующем этапе.
- Все пользователи (администраторы и бизнес-заказчики) находятся в одном корпоративном домене — актуально для последующей интеграции с AD после MVP.
- Логика взаимодействия скрипта с целевой системой (прямой вызов API vs. генерация файла) определяется индивидуально для каждого скрипта.

## Открытые вопросы

- Точный порог неудачных попыток входа и длительность блокировки при переходе к автоматической защите (после MVP).
- Состав и структура доменных групп для будущей интеграции с AD (группа X и другие).
- Детальный перечень типов документов/полномочий, которые сможет настраивать бизнес-пользователь при загрузке сертификатов/счетов.
