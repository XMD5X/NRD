# Развёртывание и редеплой на этой машине (Windows) — статус и процедура

> Исторически этот файл был техзаданием на первую сборку/деплой MVP на этой
> машине. Первый деплой давно выполнен успешно; ниже — актуальная процедура
> для повторного деплоя после изменений в коде, плюс типичные проблемы.

## Текущий статус

Стенд собран и работает через Docker Compose (backend, web/nginx, postgres —
3 контейнера). Панель доступна на **http://localhost:18080**, backend напрямую —
на **http://localhost:18081**. Проверены: вход под обеими демо-учётками, запуск
реальных скриптов поддержки (все категории — см. `README.md`), скачивание
результата (в т.ч. zip при нескольких файлах), страница истории выполнений.

## Процедура редеплоя после изменений в коде

1. Если менялся **только backend** (`backend/`) — можно сразу переходить к шагу 3,
   Maven-сборка происходит внутри Docker.
2. Если менялся **frontend** (`frontend/src/`) — собрать его вручную и обновить
   `frontend/dist-prebuilt/` **до** деплоя (см. `README.md`, раздел "Особенность
   сборки frontend на этой машине" — сборка внутри Docker на этой машине не
   работает, поэтому пересобранная статика подкладывается заранее):
   ```
   cd frontend
   npm ci
   npm run build
   ```
   и скопировать содержимое `frontend/dist/` поверх `frontend/dist-prebuilt/`.
3. Убедиться, что **Docker Desktop запущен** (иконка кита в трее) — если нет,
   `deploy.bat` упадёт с ошибкой подключения к `dockerDesktopLinuxEngine`, нужно
   сначала открыть Docker Desktop и подождать ~30–60 секунд.
4. Запустить `deploy.bat`. Он выполняет `docker compose up --build -d`; при
   успехе печатает `[+] up 5/5` и адрес панели.
5. Подождать 20–30 секунд, пока backend полностью стартует (Flyway-миграции,
   Spring context), затем открыть `http://localhost:18080` и проверить базовый
   сценарий: вход, список задач, запуск любого скрипта.

## Типичные проблемы

- **`unable to get image ...: failed to connect to the docker API at
  npipe:////./pipe/dockerDesktopLinuxEngine`** — Docker Desktop не запущен.
  Запустить его и повторить `deploy.bat`.
- **Изменения во frontend не видны после деплоя** — забыли пересобрать
  `dist-prebuilt/` перед `deploy.bat` (см. шаг 2 выше); Docker-сборка frontend
  просто копирует уже готовую папку, сама `vite build` не запускается.
- **Страница виснет на "Загрузка..." при открытом длительное время стенде** —
  истекла JWT-сессия. Раньше backend в этом случае ошибочно отвечал 403 вместо
  401, и фронтенд не понимал, что нужно перекинуть на `/login` (тикет исправлен —
  `SecurityConfig` теперь явно возвращает 401 через `authenticationEntryPoint`,
  а `DashboardPage.jsx` не виснет даже на прочих ошибках). Если увидите это на
  старой (не пересобранной) версии — просто обновите страницу или перелогиньтесь.
- **`docker compose logs backend --tail=100`** — если backend не поднимается,
  смотреть здесь: чаще всего ошибки Flyway-миграций
  (`backend/src/main/resources/db/migration/`) или проблема подключения к
  `postgres` (проверить `docker compose ps`, что `postgres` в статусе `healthy`).
